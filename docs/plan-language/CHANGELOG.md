# Plan language changelog

Newest entry first. Each entry names the sha256 of `plan.schema.json` as it stood after the change, and `npm run lint` fails when the newest entry does not name the committed schema's hash, so the schema cannot change without an entry here. Regenerate the schema with `node tools/check-plan-schema.ts --write`, which prints the hash to record.

## 1.3 (unreleased)

Schema sha256: `d75ca8294c5f82a0fca85ce621d85913fa255c2403e6b315f62f5303cb182b72`

1.3 is 1.2 plus six opt-in unsafe features and nothing else (SPEC-36). 1.2 stays the closed language, so the coverage study's closed share keeps meaning what it measured.

- A plan declares `"version": "1.3"` to use an unsafe feature. A plan declaring `"1.2"` or `"1.1"` parses and hashes exactly as before, and a 1.3 construct in it is refused with the code that version's parser gives (`unknown_value`, `unknown_field` or `unknown_step`), even when the project enables the feature.
- **Opt-in, per feature.** Each feature is off unless the trusted `project.json` enables it in a new `unsafeFeatures` section: `cssLocators` (feature `css-locator`), `xpathLocators` (`xpath-locator`), `domChecks` (`dom-checks`), `pageScripts` (`page-script`; with `allowInline` set to true also `inline-page-script`) and `databaseCommands` (`database-command`). A disabled feature is refused by the one plan parser with the new plan error `unsafe_feature_disabled`, at every use: a locator's `by`, an assertion's `kind`, a `remember` source's `read`, a step's `type`, or an inline script's `script.inline`. Nothing under it is read or echoed.
- **CSS and XPath locators.** Wherever a plan takes a locator, two new kinds: `css` with a `selector` (`{ "by": "css", "selector" }`) and `xpath` with an `expression` (`{ "by": "xpath", "expression" }`), each with `position`, `hasText` (literal text or a value reference; keeps matches whose normalised text contains it) and `inside` (any locator, the selector evaluated within the one element it finds; at most 3 deep, the fourth `inside` is `too_large`). A selector or expression is literal text of 1 to 512 characters (longer is `too_long`), never a value reference (`wrong_type`), with no line break, `{`, `}`, `;` or `@` (`unsafe_text`).
- **DOM checks.** New element assertions `hasClass` and `lacksClass` (one class token), `computedStyleEquals` (`property`, a lowercase CSS property name, and the `value` `getComputedStyle` gives), `attributeEquals` (`name`, lowercase letters, digits and hyphens, and a `value`, literal or a value reference) and `attributeAbsent` (`name`). `remember` may read an element's `attribute`: `{ "element", "read": "attribute", "attribute" }`.
- **Page scripts.** New steps `evaluate` (`{ "script", "arguments", "remember" }`) and assertion step `expectScript` (`{ "script", "arguments", "field", "assert", "criterionId" }`, on a `read` script, with the checks of `expectBackend`, repeated until it passes or the new limit `scriptCheckTimeoutMilliseconds` runs out: default 10000, at most 120000). `script` names a script declared under `unsafeFeatures.pageScripts.scripts` (a `.js` file under `plans/scripts/`, typed parameters other than secrets, `effect`, result `fields`, `allowInProposals`, `timeoutMilliseconds` and `maximumResultBytes`), or is `inline`, `{ "inline": { "source", "effect", "fields" } }`, with the script's text, 1 to 4,000 characters. Both may stand in a `frame` or `newTab`. Declared script files are trusted files: a change that edits one raises `changed-with-code`.
- **Database commands.** New step `database` (`{ "command", "arguments", "remember" }`), which may also stand in `cleanup`, and assertion step `expectDatabase` (`{ "command", "arguments", "field", "assert", "criterionId" }`, on a `read` command). `command` names a command declared under `unsafeFeatures.databaseCommands.commands`: a declared service that is `private` and has the new service field `port`, a workload image by digest, an `argv` of literals and whole-argument parameters (the first always literal), typed parameters other than secrets, an `environment` of literals and secrets, `effect`, `successExitCodes` (default `[0]`), `output` `none` or `json` with `fields`, `allowInProposals`, `timeoutMilliseconds` and `maximumOutputBytes`. Neither may stand in a `frame` or `newTab` (`misplaced_step`).
- Undeclared scripts, commands and fields, wrong arguments, a secret reference as an argument and a `write` script or command in a check reuse the existing codes.
- **Policy gate.** A proposal holding an inline script is denied with the new policy rule `inline-script-in-proposal`. A proposal running a `write` script or `write` command whose declaration does not set `allowInProposals` is denied with `side-effect-in-proposal`, cleanup included. A command whose service is on a production origin is denied with `production-origin`, approved or not. Scripts and commands count toward `maximumCalls`. The runtime guard judges every element a CSS or XPath locator resolves as any other; `unnamed-control` applies unless the exact selector or expression is listed in `unnamedControlsAllowed` in the `unsafeFeatures` section.
- **Labels.** A run of a plan using any feature carries `unsafeFeatures` in its result and manifest, beside the plan hash, and its guarantee statement is at the `host` level, naming each lost guarantee and the feature that lost it. The manifest also records `unsafeDeclarations`: the sha256 of each named script's source and of each command declaration the plan uses. A closed run carries neither field, so its hashes are unchanged. A plan naming a script whose source the run was not given is refused with the new run refusal `script-source-missing`.
- **No readable form yet.** A plan using an unsafe feature is written as JSON: `readablePlanText` refuses it with the new readable plan error `no-readable-form` at the construct's path.
- **Coverage study.** The report shows the closed-language share and the "1.3 with unsafe features" share side by side, overall and per sample. The kill criterion is decided by the closed share.
- Until the CDP driver resolves them (SPEC-06), runs report CSS and XPath locators, DOM checks and page-script steps as failed with `unsupported-step`, and until the workload runner lands (SPEC-35, SPEC-07) database steps too, with nothing sent to the page and no command run.

## 1.2 (2026-10-29)

Schema sha256: `67e316ba8c9cf1e08572ea4b91793e6ff1343363d02aac8d7cb08b489251423d`

This is the one 1.2 entry: SPEC-30 to SPEC-34 added their bullets here. Every 1.2 parser part has landed, so it is dated, and the hash above is the schema as it stood when 1.2 was the newest version.

- A plan declares `"version": "1.2"` to use the features below. A plan declaring `"1.1"` parses exactly as before: 1.1 is a subset of 1.2, and a 1.2 field or step in a `"1.1"` plan is refused with the code a 1.1 parser gives (`unknown_field`, `unknown_step`, `unknown_value` or `wrong_type`). `migratePlan` still outputs a 1.1 plan.
- **Run values.** New optional top-level `values`: named values generated for each run, from the run's seed and clock start: `uniqueText` (prefix, "-", 10 base-36 characters), `uniqueEmail` (on a domain the project declares in `generatedEmailDomains`, default `example.com`), `uniqueNumber` (4 to 12 digits) and `date` (a day relative to `today`, `startOfWeek`, `startOfMonth` or `startOfNextMonth`, in the target's time zone, written as `yearMonthDay`, `dayOfMonth`, `monthAndYear`, `longDate`, `weekday`, `timestamp` or `epochMilliseconds`).
- **Remembered values.** New step `remember`: `{ "name", "from": { "element": <locator>, "read": "text" | "value" } }`. Runs report it as `unsupported-step` until the CDP driver reads it through the prober.
- **Value references.** `{ "valueName": … }` may stand where a plan writes text for the page: fill values and lines, select options, locator names, labels, texts and test ids, text assertions' expected values, `dialog` expected text, and path-template segments and query values. Anywhere else it is refused. A reference to a value not yet defined is refused with the new plan error `undefined_value`; a name defined twice with `duplicate`.
- **Path templates.** `navigate` may take `{ "segments": […], "query": {…} }`: a path on the run's base URL, each value percent-encoded as a whole segment or query value. Literal segments holding `/`, `?` or `#` are refused (`unknown_value`), and `.` or `..` too (`invalid_url`). At run time a value of `""`, `.` or `..` fails the step with `value-unsafe` before any navigation.
- **Plan clock.** New optional top-level `clock`: `{ "day": <relative day>, "time": "HH:MM" }` sets the page's frozen clock in the target's time zone. The manifest keeps the run's own clock start.
- **Positions.** Every locator takes an optional `position`: `first`, `last` or 1 to 1000, in document order. `countEquals` and `absent` on a positioned locator are refused with the new plan error `position_not_allowed`.
- **Declared test-id attributes.** A `testId` locator may name `attribute`, one of the project's `testIdAttributes` (default `data-testid`; each `id` or `data-…`).
- **Key chords and more keys.** `press` takes optional `modifiers` (1 to 4 distinct of `Alt`, `Control`, `Meta`, `Shift`, `ControlOrMeta`). New keys: `a` to `z`, `0` to `9`, `Backquote`, `Minus`, `Equal`, `BracketLeft`, `BracketRight`, `Backslash`, `Semicolon`, `Quote`, `Comma`, `Period`, `Slash` and `F1` to `F12`. The policy gate judges Enter or Space with modifiers as without them.
- **Multi-line text.** A `fill` value may be `{ "lines": […] }`, joined with line feeds, within the project's new `limits.maximumFillLines` (default 50) and `limits.maximumFillCharacters` (default 4000, line breaks included).
- **URL prefix.** New page assertion `urlPathStartsWith`, whose value starts with `/`.
- New run-time step errors decided by the engine: `value-empty`, `value-unsafe` and `value-too-long`.
- Until the CDP driver supports them, runs report positions, test-id attributes other than `data-testid`, key chords, multi-line fills and `remember` as failed with `unsupported-step`, with nothing sent to the page.
- **Accessibility states.** New element state checks `selected`, `unselected`, `expanded`, `collapsed`, `pressed`, `unpressed` and `current`, read from the accessibility tree (`aria-selected`, `aria-expanded`, `aria-pressed`, `aria-current` and their native equivalents). An element that does not expose the state fails with the new step error `state-not-exposed`.
- **Link target.** New element assertion `hrefEquals`: literal text or a value reference, an absolute http or https URL or a path starting with `/`, compared with the link's resolved URL. The link is never followed.
- **Page metadata.** New page assertions `metaContent` (`{ "name", "value" }`: the content of the `<meta>` whose `name` or `property` is `name`; script-like names are refused with `unsafe_text`) and `canonicalUrl` (the resolved `href` of `<link rel="canonical">`, any origin, since it is compared and never visited).
- **Server-rendered view.** `navigate` takes optional `scripts`, whose only value is `"disabled"`: script execution stays off until the next `navigate`. Other text is refused with `unknown_value`, anything else with `wrong_type`.
- **Downloads.** New step `download` (`{ "name", "locator" }`): a click that must start exactly one download, guarded by the policy gate as a click. New step `expectDownload` (`{ "download", "assert", "criterionId" }`), an assertion step, with checks `fileNameEquals`, `mediaTypeEquals`, `sizeAtLeast` (at least 1; 0 is `vacuous`), `sizeAtMost`, `contentContains` and `contentExcludes`. A download name is lowercase letters, digits and hyphens (1 to 64, else `unknown_value`), defined once in the plan-wide namespace it shares with run values (`duplicate`), and checked only after its `download` step (`undefined_value`). New project settings: `maximumDownloadBytes` in `limits` (default 5 MiB, at most 100 MiB) and `keepDownloads` in a new `evidence` section (default false; download content is never kept before redaction lands). New driver errors `no-download` and `download-too-large`, and step error `download-not-text`.
- **A second tab.** New step `newTab` (`{ "url", "steps" }`): opens a URL on the allow-list, or a path template, in a new tab of the same browser context, runs its steps there and closes the tab. Only the top level of a plan may hold one; a `newTab` inside a `frame` or another `newTab` is refused with the new plan error `misplaced_step` at the step. Frame depth counts from the tab. The policy gate judges the tab's URL and steps exactly as in the first tab.
- Until the CDP driver supports them, runs report the new state checks, `hrefEquals`, `metaContent`, `canonicalUrl`, `navigate` with `scripts`, `download`, `expectDownload` and `newTab` as failed with `unsupported-step`, with nothing sent to the page.
- **Declared service calls.** The trusted project gains `services` (`{ "name", "origin", "private" }`; a name is a lowercase letter, then up to 39 lowercase letters, digits or hyphens) and `calls`: named HTTP calls, each with its service, method, path, query, headers and JSON body as templates, typed parameters, `effect` (`read` or `write`), `successStatuses`, response `fields` as JSON pointers, `allowInProposals`, `timeoutMilliseconds` (default 10 s) and `maximumResponseBytes` (default 1 MiB). A parameter fills a whole path segment, query value or JSON value; inside a string only types that cannot hold quotes, spaces or separators may be written, else the new plan error `unsafe_interpolation`. A header that decides where or how a request travels is refused with the new plan error `header_not_allowed`. New `limits`: `maximumCalls` (default 20, at most 200) and `backendCheckTimeoutMilliseconds` (default 10000, at most 120000).
- **Call steps.** New step `call` (`{ "call", "arguments", "remember" }`): invokes a declaration by name with arguments typed by it (literal values, run values, or `{ "secretName" }` for a secret parameter) and may `remember` response fields as run values. New assertion step `expectBackend` (`{ "call", "arguments", "field", "assert", "criterionId" }`) on a `read` call, with checks `present`, `absent`, `equals`, `contains` and `numberEquals`, repeated until it passes or `backendCheckTimeoutMilliseconds` runs out. New optional top-level `cleanup`: calls that run in order after the steps, whatever the outcome. Undeclared calls and fields, wrong arguments and a `write` call in `expectBackend` reuse the existing codes; a call inside a `frame` or `newTab`, or any other step in `cleanup`, is `misplaced_step`. A plan cannot write a URL, method, header or body.
- **Running calls.** Calls go through the run's service caller; a plan that calls a service with none wired in is refused with `services-unavailable`, and a secret a call needs that the store lacks with `secret-missing`, before any side effect. A failed `call` ends the run `Errored` and cleanup still runs; a failed `expectBackend` ends it `Failed`. New service call errors: `parameter-invalid`, `unexpected-status`, `call-timeout`, `service-unreachable`, `egress-blocked`, `response-not-json`, `response-too-large`, `field-missing` and `cleanup-failed` (recorded in the result's `cleanup`, raising a review item, never changing the verdict). A run with calls lists `service-calls` among its non-hermetic inputs. The policy gate denies a proposal's `write` call whose declaration does not allow it in proposals (`side-effect-in-proposal`), calls over `maximumCalls` (`over-limit`) and a service on a production origin (`production-origin`). Runner's real caller, through the egress proxy, comes with SPEC-07.
- **Declared stubs, request checks and storage.** The trusted project gains three sections of named declarations (each name a lowercase letter, then up to 63 letters and digits). `stubs`: a request matcher (`{ "origin", "method", "path", "match": "exact" | "prefix" }`, on an allowed origin or a declared service's, else `origin_not_allowed`), typed `parameters`, 1 to 20 `responses` served in order, the last repeating (none is `empty`, more is `too_large`), and `allowInProposals`. A response has a `status` from 200 to 599, a `mediaType` from `application/json`, `application/problem+json`, `text/plain` and `text/csv` only (else `unknown_value`), optional `headers` and a `body`: `{ "fixture" }` (a declared fixture), `{ "json" }` (a template on the stub's parameters), `{ "text" }` or `null`. A header that changes how the browser treats a response (`set-cookie`, `location`, `content-type`, `content-security-policy…`, `access-control-…`, `cross-origin-…` and the like), and `x-content-type-options`, which the engine always sends as `nosniff`, are `header_not_allowed`. `observedRequests`: a matcher, optional response `fields` as JSON pointers and `maximumResponseBytes` (default 256 KiB). `storageEntries`: `area` (`local` or `session`), an allowed `origin`, `key`, `access` (`read` or `readWrite`) and, for `readWrite` only, a `value` template with `parameters`; plus `allowInProposals`. New limit `requestQuietMilliseconds` (default 500, at most 5000).
- **Stub, request and storage steps.** New step `stub` (`{ "stub", "action": "start" | "stop", "arguments" }`; arguments only with `start`, and a `stop` only after the stub's `start`, else `unknown_value`), which may stand in a `frame` or `newTab` and applies to the whole browser context. New step `resetRequests` (`{ "request" }`). New assertion steps `expectRequests` (`{ "request", "count", "criterionId" }`, a count of `equals`, `atLeast` or `atMost`; `atLeast` 0 is `vacuous`), `expectResponse` (`{ "request", "assert", "criterionId" }` on the latest exchange, with checks `statusEquals`, `fieldPresent`, `fieldAbsent`, `fieldEquals` and `fieldContains`) and `expectStorage` (`{ "entry", "assert", "criterionId" }`, with checks `present`, `absent` and `equals`). New steps `setStorage` (`{ "entry", "arguments" }`) and `removeStorage` (`{ "entry" }`), on `readWrite` entries only (a `read` entry is `unknown_value`). `remember` may read a response field: `{ "response", "field", "read" }`, as `text` or as `arrayLength`, the decimal length of an array. Undeclared names and fields and arguments that do not fit reuse the existing codes; a plan cannot write a matcher, a response, a header, a storage key or a value to store. New step error `request-not-seen` and driver error `storage-origin-mismatch`. The policy gate denies a proposal that starts a stub or writes or removes an entry whose declaration does not allow it in proposals (`side-effect-in-proposal`). Until the CDP driver's network and storage ports land (SPEC-06 and SPEC-07), runs report every one of these steps, and a `remember` from a response, as failed with `unsupported-step`, with nothing sent to the page.
- **Advancing the clock.** New step `advanceClock` (`{ "by": { "amount", "unit" }, "mode" }`): moves the run's virtual clock forward by a whole `amount` of at least 1 (else `wrong_type`, a missing amount included) of `milliseconds`, `seconds`, `minutes`, `hours` or `days` (a day is 86,400,000 ms of elapsed time), with no real wait. In mode `runTimers`, the default, every page timer that comes due within the advance fires at its own virtual time; in `skipAhead` the clock jumps and each timer now due fires once. Another unit or mode is `unknown_value`; a `script`, `sleep`, `until` or any other field is `unknown_field`; there is no `sleep`, `wait`, `setClock` or `pauseClock` step (`unknown_step`). It may stand anywhere, inside a `frame` or `newTab` too, and is not an assertion step. New `limits`: `maximumClockAdvanceMilliseconds` (default one hour, at most 31 days; an advance over it is `too_large` at its amount), `maximumTotalClockAdvanceMilliseconds` (default one day, at most 31 days; the plan's advances are added up, those in `frame` and `newTab` blocks included, and the step that first passes it is `too_large`) and `maximumTimersPerAdvance` (default 10,000, at most 100,000). Each is at least 1, and a step limit above the plan limit refuses the project with `too_large` at the step limit. New driver error `clock-runaway`: one advance would fire more timer callbacks than `maximumTimersPerAdvance`.
- **Checking the clipboard.** New assertion step `expectClipboard` (`{ "assert", "criterionId" }`), with checks `textEquals`, `textContains` and `textExcludes` of the run's own in-memory clipboard, never the host's. Expected text is literal text or a value reference, and for `textEquals` also `{ "lines": […] }`, joined by line feeds, within `maximumFillLines` and `maximumFillCharacters` (no lines is `empty`; lines for the other checks are `wrong_type`). Empty expected text is `vacuous`, script-like text `unsafe_text`; a `pattern`, `regex` or `script` field is `unknown_field`; there is no `writeClipboard`, `setClipboard` or `paste` step (`unknown_step`). An empty clipboard fails every check, `textExcludes` included. `remember` gains the source `clipboard`: `{ "clipboard": "text" }`, the only clipboard format (another is `unknown_value`), under SPEC-30's remembered-value rules, so multi-line text fails with `value-unsafe`. New limit `maximumClipboardCharacters` (default 20,000, at most 200,000; longer clipboard text fails with `value-too-long`). New driver error `clipboard-unavailable`: the browser cannot keep the clipboard in its own memory. The policy gate allows both steps in proposals: neither sends input.
- Until the determinism kit's timer tracking and the CDP driver's clock and clipboard ports land (SPEC-06 and SPEC-08), runs report `advanceClock`, `expectClipboard` and a `remember` from the clipboard as failed with `unsupported-step`, with nothing sent to the page and no real wait.

## 1.1 (2026-10-28, secrets)

Schema sha256: `a8de4ce560a15ff02b1e6eaec657d2e4465efa825a956a5b8ef33bb15e07e6bc`

- Still `"version": "1.1"`: the change only adds an optional field, so every plan that parsed before still parses the same way, except plans holding a literal secret (below).
- New optional top-level field `storageState: { "secretName": … }`: saved browser storage state (cookies and local storage), named like any secret the project declares in `secretNames`. The secret's value is the storage-state JSON. The run records only its name and sha256; loading it into the browser session comes with the driver's session environment.
- New plan error `literal_secret`: literal text filled into a field whose locator names a password, passcode, token, secret or API key (also in German and French), credential-shaped text anywhere in the plan (a JSON Web Token, `Bearer …`, or a known key prefix such as `ghp_`, `sk-` or `AKIA`), or storage state written into the plan itself.
- Secret references in `fill` now run: the browser drivers type the resolved secret. A run whose plan names a secret the store cannot resolve is refused with `secret-missing` before any browser opens.

## 1.1 (2026-10-28)

Schema sha256: `906726f3b06796ba6c9a7e8b8745362db90d29893520e61052e92b25ed1036cb`

- First published schema. A plan declares `"version": "1.1"`.
- New steps: `hover`, `select`, `upload` (a file the project declares in `fixtures`), `frame` (steps inside an iframe, nested up to the project's `maximumFrameDepth`) and `dialog`.
- A `fill` value may be a reference `{ "secretName": … }` to a secret the project declares in `secretNames`, instead of literal text.
- New element assertions: `absent` (no element matches; `hidden` also passes for one element that is present but not shown), `checked`, `unchecked`, `focused` and `countEquals`; new page assertion `url`.
- New roles: `listbox`, `menuitem`, `table`, `row`, `cell` and `form`. New keys: `Delete`, `Home`, `End`, `PageUp` and `PageDown`.
- Every `expect` and `expectPage` step carries a `criterionId`: the acceptance criterion it checks. A plan with no assertion, an empty assertion or an assertion without a `criterionId` is rejected as `vacuous`.
- Version 1 plans are accepted for 12 months, only through `migratePlan`, which takes a criterion id for each assertion keyed by its JSON path and fails with `no_criterion_id` for any assertion left out.
- Until the browser drivers support them, runs report `hover`, `select`, `upload`, `frame` and `dialog` steps, secret references and the `checked`, `unchecked` and `focused` assertions as failed with `unsupported-step`.
