# Refactor assumptions to validate

## In short

The founder asked (2026-11-08) for the refactor to run to the end without stopping, taking the recommended option each time and listing the assumptions for validation afterwards. This is that list. Each row says what was decided, why, what else was possible and how to reverse it.

## Decisions

| # | Part | Assumption made | Why | Alternative | To reverse |
|---|---|---|---|---|---|
| 1 | Split `cdp-driver` | The `REVEAL_ALLOWED_MODULES` entry moved from `browser-session.ts` to `session/TextToFill.ts` is a move, not a new entry, so it did not wait for a ruling, though the review brief sends new entries to the founder | The same one reveal, for the same fill, moved with its code. The module now sends the text itself and returns nothing | Hold the part until the founder rules | Change the entry in `tools/check-secret-reveal.ts` |
| 2 | Split `cdp-driver` | The session port gained `recordsSoFar()`, used only for a close that does not finish | A run whose close hangs must keep its egress records and result hash, and a `close()` that has not returned has no value to read | Let such a run end Errored with its egress unread, which changes the result hash | Remove the member and accept the hash change |
| 3 | Split `cdp-driver` | Closing a tab never rejects; a failure is reported by the session's close. An engine branch and a test fake for a rejecting tab are removed | This is what the real driver does, and one rule lets an adapter be written from the port alone | Have a tab's close give an outcome | Add the outcome to the port |
| 4 | Split `cdp-driver` | Committed proofs and test fakes were changed where the refactor forced it, without stopping, though the build loop normally stops to ask before changing a committed test | The founder said not to stop; no assertion was loosened | Stop and ask for each | Read the tests commits of this part |
| 6 | Split `cdp-driver` | A driver that throws against its `Result` contract ends the run `Errored`, in a new public result shape `PlanDriverBrokeResult` (no manifest, no steps), not `TargetUnavailable` | A broken driver says nothing about the target, and a result must not blame it | Report `TargetUnavailable`, as defect row 302 first proposed | Change `engine/src/target/GuardedDriver.ts` and its test |
| 7 | Split `cdp-driver` | Only the text "No frame for given id found" counts as a frame in another renderer process. **Not observed:** it comes from the existing pattern and memory of Chromium's source, and no test uses a real cross-process iframe | Everything else must surface as `dialog-open` or `timeout`, not `unsupported-step` | Test against a real cross-process iframe | If the text differs, such a frame gives `not-actionable`; correct the match in `page/CdpPage.ts` |
| 8 | Split `cdp-driver` | Windows stop reads taskkill's English output to tell that a tree has ended. In any other Windows language it falls back to asking the browser to close, as before | taskkill gives exit code 255 for both outcomes, so only its text tells them apart | Treat every 255 as ended, which would hide an access-denied stop | `launch/LaunchChromium.ts` |
| 9 | Split `cdp-driver` | Once taskkill has ended the tree, stop waits up to 12 s for Node to see the browser exit, up from about 5 s | Under load the exit was seen late and stop wrongly reported the browser as left. It only waits; nothing is sent again | A shorter wait, with the rare false report | `launch/LaunchChromium.ts` |
| 10 | Split `cdp-driver` | A crawl keeps its own outcome when its browser fails to close, and the close failure's text goes to a new optional `closeFailure` field in the CLI's output and a human-readable line | Clean-up mustn't change a verdict but must be reported | Fail the crawl | `cli/src/explore-crawl.ts` |
| 11 | Split `cdp-driver` | Masking walks same-process iframes through their elements, and a capture with a frame out of reach fails. That frames in another process are missing from `Page.getFrameTree` is **from memory, not checked**; the walk doesn't depend on it | Personal data must not reach an image. Failing is stricter than before, so a page with an out-of-process frame can no longer be captured with masks | Leave it to SPEC-09 | `in-page/MaskElements.ts`, `session/ScreenshotDocument.ts` |
| 12 | Split `cdp-driver` | `CloseKeepingTheResult` gives a prompt close 4 zero-time turns instead of 1, a named constant, because the new guard adds a promise step | Without it, 27 tests measured a 50 ms poll instead | Restructure the close so no turn count is needed | `engine/src/run/session/CloseKeepingTheResult.ts` |
| 13 | Split `egress-proxy` | Connecting to a name's vetted addresses in turn now shares one 30 s deadline, each attempt getting the time left divided by the addresses left, rather than 30 s per address | The review brief allows trying again only under one deadline, and four dead addresses took 120 s. A fair share stops a dead first address starving the rest. `docs/decisions/host-egress-proxy.md` approves the walk itself, which stays | Keep 30 s per address | `egress-proxy/ConnectInTurn.ts` |
| 14 | Split `egress-proxy` | A fixture body being rewritten is capped at 32 MiB, and rewriting works on bytes, so a body that isn't UTF-8 stays intact. Over the cap the proxy answers 502 | Buffering was unbounded. The figure is my choice; no document sets one | Another cap, or streaming | `egress-proxy/AnswerDelivery.ts`, `RewriteBody.ts` |
| 15 | Split `egress-proxy` | A request with a body keeps its chunked framing whatever its method, and a CONNECT authority with user information is refused | Both stricter. Node dropped the framing for DELETE, which let a chunk reach upstream as a second request | Refuse chunked requests on such methods | `egress-proxy/ForwardedHeaders.ts`, `ParseConnectTarget.ts` |
| 16 | Split `egress-proxy` | An unknown or empty egress decision mark on a service call reads as `egress-blocked` | It fails closed and needs no new error code | A separate error code for an unreadable mark | `runner/src/service-caller.ts` |
| 17 | Split `egress-proxy` | The one origin reader moved to `contracts` (`ParseOrigin.ts`), so `contracts` now holds a small parser, and the runner uses it. Applied rewrites and proxy rules now refuse any origin that isn't http or https | Two readers gave one brand two meanings | Keep a second reader in the runner | `tools/check-branded-casts.ts` |
| 18 | Split `egress-proxy` | The proxy container calls `process.exit` on a non-zero result, and a second `close()` repeats the first outcome | Otherwise the refusals server keeps a failed container alive | Have the server closed first | `runner/src/proxy-container.ts` |
| 19 | Runners' shared lifecycle | The `Runner` port becomes `withRun` alone: `start`, `stop`, `guaranteeLevel` and `latestRun` go, and the level comes from the run itself. Tests that read `runner.guaranteeLevel()` before any run were removed, because that can no longer be asked | With overlapping runs, a port-level read could report a `host` run as `isolated` | Keep the port-level read | `contracts` isolated-runner port |
| 20 | Runners' shared lifecycle | After a timeout, a workload's wait for its command is bounded at 10 s, ending in a named outcome. The figure is my choice | A wedged daemon otherwise hangs the run for ever | Another figure | `runner/src/workload/RunCommandUnderTimeout.ts` |
| 21 | Runners' shared lifecycle | A null gateway address (a container holds the subnet's first address, which Docker gives out only to a network with no gateway) skips only the gateway probe, and a run can still claim `isolated` from the public probes. Not confirmed on real Docker | The existing tests pin this, and treating null as not isolated would drop those runs to `host` | Treat null as not isolated | `runner/src/run-containers.ts` |
| 22 | Runners' shared lifecycle | A timed-out suite still publishes `exitCode: -1` in its evidence and recording, though the internal outcome has no exit code. A crashed crawl is reported as `explore-runner-unavailable` with a reason, because the CLI's error codes are pinned | Changing either would alter a published shape or a pinned list for little gain | Publish null, or add a distinct CLI code | `runner/src/workload/`, `cli/src/draft-command.ts` |
| 5 | Split `cdp-driver` | `PageWatch.ts`, 422 lines with four concerns, stays whole for now. Prettier is held back on it, `Actionability.ts` and `PageAudit.ts`, which it would push over the length limits | The review marked it `consider` and nothing is wrong yet | Split popup holding out now | Split it in phase 4 |
