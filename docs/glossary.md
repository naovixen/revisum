# Glossary

## In short

- Each domain term, the name it has in code, and where that name lives. Use these names; add a row when you add a term.
- "Planned" means the spec named in the row introduces the code name; it does not exist yet.
- Older names from the research are listed only so readers of the specs can map them. Never use them in code.

## Domain terms

| Term | Code name | Where | Meaning |
|---|---|---|---|
| Product name | `PRODUCT` (`PRODUCT.name`, `PRODUCT.schemaNamespace`) | `contracts`, exists | The only place the product name is written; schema ids are built from it |
| Engine | `engine` package | `packages/engine` | The trusted core: parsing, trust, policy, lifecycle, interpreter, oracle, hashing, redaction, audit log |
| Package | npm workspace | `packages/*` | One unit of the monorepo, with its own licence and allowed imports |
| Plan | `Plan`, made only by `planParser`; `assertBranded` checks it at run time | type in `contracts`, parser in `engine`, exists | A human-approved, typed test plan in language version 1.3, the only version a plan may declare; outside input until the engine parses it |
| Step | `Step`, `ActionStep`, `DialogStep` | `contracts`, exists | One instruction in a plan, from a closed set: navigate, click, hover, fill, select, upload, press, frame, dialog, expect, expectPage, a11yAudit, capture, remember. An action step sends input to the page through the driver, which asks the runtime guard first; a dialog step is one, answering the dialog the page opened |
| Plan schema | `planJsonSchema`, `docs/plan-language/plan.schema.json` | `engine`, exists | The published JSON Schema of the plan language, built from the parser's own tables; necessary, not sufficient |
| Secret reference | `SecretReference` (`SecretName`) | `contracts`, exists | A fill value, or a plan's `storageState`, that names a secret the project declares, instead of holding it |
| Secret | `Secret`, `createSecret`, `reveal` | `contracts`, exists | A secret's value wrapped so that printing, serialising or inspecting it gives `[secret]`; only modules in `REVEAL_ALLOWED_MODULES` (`tools/repo-rules/code/CheckSecretReveal.ts`) may import `reveal` |
| Secret store | `SecretStore`, `environmentSecretStore` | port in `contracts`, environment store in `engine`, exists | Resolves a secret name to a `Secret`; the MVP reads CI secrets from environment variables of the same name. A run takes it as the optional `secrets` port |
| Literal secret | `literal_secret` | `engine`, exists | A secret written into a plan: literal text in a sensitive field, credential-shaped text, or storage state itself. The parser rejects it |
| Secret redaction | `secretRedaction`, `RedactionMode` (`value`, `key-only`), `MINIMUM_SECRET_LENGTH` | `engine` and `contracts`, exists | Removes a secret's echoes (raw, URI, base64, base64url, any case, prefixes) from kept text; secrets shorter than the minimum are redacted by key, never searched for |
| Leak scanner | `leakScanner`, `LeakScanner`, `Leak` (`LeakForm`) | port in `contracts`, scanner in `engine`, exists | Scans a run's output files, images included, for echoes of secrets; the caller plants a canary it must find |
| Saved storage state | plan `storageState`, manifest `storageState` (`StorageStateRecord`) | `contracts` and `engine`, exists | A browser's exported cookies and local storage, held as a secret; the manifest records only its name and sha256 |
| Upload fixture | `FixtureName` | `contracts`, exists | A file the project declares in its `fixtures` list, which an upload step may send. Not the app files a run serves (`FixtureReference`) |
| AI text | `AiText`, made only by `parseAiText` | `engine`, exists | Text an AI writer returned that passed the text rules; stored only as a suggestion |
| Locator | `Locator`, `ResolvedLocator`, `literalLocator` | `contracts`, exists | How a step finds an element: by role and name, label, text or test id, optionally at a `position` (first, last or nth) and, for a test id, on a declared `attribute`. From plan 1.3, also by a CSS selector or an XPath expression (a structural locator). Resolved: every value reference replaced with its text |
| Run value | `GeneratedValue` (plan `values`), `remember` step, `ValueName`, `RunValues`, `generateValue` | `contracts` and `engine`, exists | A value a plan names and uses where it would write text: generated per run from the seed and clock start (unique text, email, number, or a date relative to the clock), or remembered from the page |
| Declared service | `DeclaredService`, `ServiceName` (project `services`) | `contracts`, parsed in `engine`, exists | A backend the trusted project names, with its origin and whether it may resolve to a private address |
| Declared call | `CallDeclaration`, `CallName`, `ParameterType`, `JsonTemplate` (project `calls`) | `contracts`, parsed in `engine`, exists | A named HTTP call a person declares in the trusted project: service, method, path, query, headers and body as templates, typed parameters, effect, success statuses, pending statuses (`pendingStatuses`: "not ready yet", which only a backend check polls on) and response fields. A plan invokes it only by name |
| Call step, backend check, cleanup | `call`, `expectBackend` steps, plan `cleanup`, `buildServiceRequest` | `contracts` and `engine`, exists | A `call` makes a declared call and may remember response fields; an `expectBackend` checks one field of a read call, polling; `cleanup` calls run after the steps whatever the outcome |
| Service caller | `ServiceCaller`, `ServiceRequest`, `ServiceResponse`, `serviceCaller` | port in `contracts`; runner's `serviceCaller`, exists | Sends a declared call's request and reads its response. A run takes it as the optional `services` port. Runner's caller sends each request once, through the egress proxy, never follows a redirect and stops reading at the size cap |
| Unwired port | `UnwiredPort`, `UNWIRED_PORT`, `isWiredPort`, `noServiceCaller`, `noDatabaseCommandRunner` | `contracts` and `engine`, exists | A port a run was given nothing to wire to: its type says so, so a wrapper can't hide it, and preflight refuses a plan that needs it before any side effect |
| Stub | `StubDeclaration`, `StubName`, `RequestMatcher`, `STUB_MEDIA_TYPES` (project `stubs`), `stub` step | `contracts`, parsed in `engine`, run through the CDP driver's network port, exists | A declared fake answer to the page's fetch and XHR requests that match a request matcher: responses served in order, the last repeating, data media types only and always `nosniff`. A plan starts and stops it by name |
| Observed request, request check | `ObservedRequestDeclaration`, `RequestName` (project `observedRequests`), `resetRequests`, `expectRequests`, `expectResponse` steps | `contracts`, parsed in `engine`, run through the CDP driver's network port, exists | A declared matcher whose exchanges the driver records, so a plan may count them and check or remember fields of the latest response |
| Storage entry | `StorageEntryDeclaration`, `StorageEntryName` (project `storageEntries`), `setStorage`, `removeStorage`, `expectStorage` steps | `contracts`, parsed in `engine`, run through the CDP driver's storage port, exists | One declared local or session storage key on an allowed origin, which a plan may check, and write or remove when declared `readWrite`. Values read are compared, never recorded |
| Value reference | `ValueReference` (`{ "valueName": … }`), `TextOrValue` | `contracts`, exists | Where a plan writes text for the page, a name of a run value instead; the run substitutes it before the policy gate's runtime guard |
| Path template | `PathTemplate` (`segments`, `query`) | `contracts`, exists | A navigate URL built on the run's base URL from literal segments and value references, each value percent-encoded as a whole |
| Plan clock | `PlanClock`, `resolvePlanClock` | `contracts` and `engine`, exists | The page's frozen time, set relative to the run's clock start in the target's time zone; the manifest keeps the run's own clock start |
| Clock advance | `advanceClock` step, `ClockAdvance`, `ClockUnit`, `ClockAdvanceMode` (`runTimers`, `skipAhead`), `clockAdvanceMilliseconds`, `totalClockAdvanceMilliseconds` | `contracts` and `engine`, exists; the CDP driver's, exists | Moves the run's virtual clock forward by a bounded whole amount, firing the page's due timers, with no real wait. Bounded per step and per plan by the project's limits. Only a plan with an advance runs the page's timers on virtual time; every other plan keeps real-time timers |
| Clipboard check | `expectClipboard` step, `ClipboardAssertion`, `remember` from `{ "clipboard": "text" }` | `contracts`, parsed and run in `engine`, exists; the CDP driver's, exists | Checks or remembers the plain text of the run's own in-memory clipboard, never the host's. The text is compared, never recorded |
| Download | `download` step, `DownloadStep`, `DownloadName`, `expectDownload` step, `DownloadAssertion`, `DownloadedFile`, `DownloadRecord` | `contracts` and `engine`, exists; performed by `cdpDriver` | A click that must start exactly one file download, named for the checks after it. The driver saves the file in a folder of the session's own under a name it generates, capped at `limits.maximumDownloadBytes`, and removes the folder when the session closes. The result keeps the file's name, media type, size and sha256; until privacy masking (SPEC-09) none of its content is kept, whatever `evidence.keepDownloads` says |
| Second tab | `newTab` step, `Session.newTab` | `contracts` and `engine`, exists; performed by `cdpDriver` | A tab the plan opens on an allowed URL in the same browser context, so cookies and storage are shared; it runs its steps and closes. Only the plan's top level may hold one |
| Server-rendered view | `navigate` with `scripts: "disabled"`, `SCRIPT_MODES`, `NavigateOptions` | `contracts` and `engine`, exists; performed by `cdpDriver` | A page loaded with script execution off until the next navigate, so the checks see what the server sent |
| Compared URL | `hrefEquals`, `canonicalUrl` | `engine`, parser exists | A URL a check compares and never visits: an absolute http or https URL of any origin, or a path starting with `/` |
| Key chord | press `modifiers` (`Modifier`, `ControlOrMeta`) | `contracts`, exists | Keys held down while a key is pressed; the policy gate judges Enter or Space with modifiers as without them |
| Multi-line text | `MultiLineText` (`{ "lines": […] }`), `limits.maximumFillLines`, `limits.maximumFillCharacters` | `contracts` and `engine`, exists | A fill of several lines, joined with line feeds and inserted with no Enter key press |
| Test-id attribute | `TestIdAttribute`, project `testIdAttributes` | `contracts` and `engine`, exists | An attribute (`id` or `data-…`) the project declares that a `testId` locator may match by exact equality; default `data-testid` |
| Generated email domain | `EmailDomain`, project `generatedEmailDomains` | `contracts` and `engine`, exists | A domain a generated unique email address may use; default `example.com` |
| Step error | `StepErrorCode` (`value-empty`, `value-unsafe`, `value-too-long`, `script-result-too-large`, `script-result-invalid`) | `engine`, exists | A run-time step failure the engine decides, as opposed to a driver error |
| Step code | `StepCode`, `StepOutcome`, `StepFailure`, `stepFailed` | `contracts`, exists | Every code a step's result can hold. A failed step always holds one; a passed step holds one only to say what it left out |
| Step result shapes | `StepResult` (`PassedStep`, `FailedStep`, `SkippedStep`), `RanStepResult`, `StepRecord` (`PassedStepRecord`, `FailedStepRecord`), `SkippedStepRecord`, `StepRecords`, `StepPlace`, `PassedStepCode`, `failedStep` | `contracts`, `failedStep` in `engine`, exists | One shape per step outcome: a failed step always holds its code and may keep a redacted observation; a passed one holds only `capture-left-out`, if any; a skipped one holds nothing but its outcome. `StepRecord` is what an executor gives back, before the run adds the index and type |
| Cleanup result | `CleanupResult`, `CleanupSubject` | `contracts`, exists | A cleanup step's record, by its call or command: passed, skipped, or failed with `cleanup-failed` and always the cause |
| Field table | `readFields`, `FieldReader`, `OptionalField`, `optionalField`, `FieldValues`, `ListedFields`, `knownField` | `engine`, exists | A table naming the fields of a plain object and the reader of each, which gives the whole object's decoder; a field wrapped in `optionalField` may be left out. `ListedFields` types a table as exactly the fields a grammar list names; `knownField` names a field already read, such as a discriminant |
| Step reader | `StepReader`, `StepReaderTable`, `StepFieldsRead`, `StepRead`, `withoutLeftOutFields`, `readWhenPresent`, `StepList` | `engine`, exists | How the plan parser reads one step type once the step's fields are checked against its fact in `STEP_FACTS`; the table holds one per step type, so a new type does not compile without one. `StepList` is a list of steps holding at least one. `StepRead` names every field of the step type, one left out as undefined, so a reader that forgets a field does not compile; `withoutLeftOutFields` then drops those, and `readWhenPresent` reads a field a step may leave out |
| Readable copy | `readableCopy`, `readOneLevel`, `ReadableInput`, `ReadableRecord`, `ReadableList`, `UNREADABLE` | `engine`, exists | The copy of a parser's input taken once at its edge, holding only own data read safely, with `UNREADABLE` for what could not be read; only `readableCopy` makes a `ReadableInput`, so a reader that probes keys can be handed nothing else |
| Inline script form | `isInlineScript`, `isInlineChoice` | `engine`, exists | Which form a page script step's script takes: `isInlineScript` on raw input in the parser, where any object is the inline form; `isInlineChoice` on a parsed `ScriptChoice` |
| Frame depth | `frameDepthInside`, `isDeeperThanAllowed` | `engine`, exists | How many frames deep a list of steps stands: the plan's own at 0, a frame's or second tab's steps at the depth of its list plus its `frameDepthAdded`. The parser and the policy gate share this one rule |
| Project | `Project`, made only by `parseProject` | `engine`, exists | The trusted, person-written configuration: allowed origins (and which are production), the target matrix, limits, the secret names and fixture files plans may refer to, and its policy (`ProjectPolicy`) |
| Target | `Target` (`TargetId`) | `contracts`, exists | One declared browser engine, device profile, locale and environment to test with. Never substituted |
| Browser driver | `BrowserDriver`, `Session` | ports in `contracts`; `cdpDriver` in `driver-cdp` (the only driver; the Playwright driver was removed on 2026-11-02, and Firefox comes through BiDi in SPEC-19) | Opens a session for a target; a session navigates, acts, probes, captures and audits |
| Closed session | `ClosedSession`, `SessionRecords`, `recordsSoFar`, `isRequestHeld` | `contracts`, exists | What `Session.close` gives once the session has closed: its `SessionRecords` (the blocked origins, connection failures and refused request decisions, each what it says or why it could not) and what stopped part of the close. `recordsSoFar` gives the same records, incomplete, while the session runs or when its close did not finish, and `isRequestHeld` says during the run whether a refused decision will be listed |
| In-page function | `PageFunction` | `driver-cdp/src/in-page/`, exists | A function that runs inside the page, sent as its source text, so it uses nothing from its module. Every one lives in a file the in-page lint rule lists, and the rule checks both |
| Shared browser | `SharedBrowser`, `BrowserSource`, `launchSharedBrowser` | `driver-cdp`, for tests only, exists | One Chromium that sessions run on one at a time, each with its own connection and browser context, to save a launch per run. Production launches a fresh browser per run |
| Run | `run`, `runUntrusted`, `RunResult`, `RunService`, `createRunService` | `RunResult` in `contracts`, the rest in `engine`, exists | Interprets a parsed plan on one target and returns a hashed result; `createRunService` is handed the run's ports once and runs cleared plans and untrusted input with them |
| Run result shapes | `PlanRunResult` (`PlanRanResult`, `PlanDeniedResult`, `PlanDeniedThenErroredResult`, `PlanRefusedResult`, `PlanDriverBrokeResult`, `TargetUnavailableResult`), `EvidenceRunResult` (`SuiteRanResult`, `SuiteRefusedResult`), `RunResultBasis`, `NothingRanFields`, `PlanRunLabels`, `PlanStepsFields`, `RunTimings`, `TerminalState`, `isDeniedRun` | `contracts`, exists | One shape per way a run can end, told apart by `state` and `mode` (and `isDeniedRun` for the two Errored plan shapes), so each carries exactly the fields it can have: a denial only when denied, a refusal only when refused, an unavailable reason only when the target was unavailable, a suite and evidence record only for an evidence run. A denied run that a record read after its steps leaves without a verdict, whichever record it was, ends Errored and always keeps its denial |
| Run refusal | `Refusal`, `RefusalCode`, `PlanRefusal`, `SuiteRefusal`, `EvidenceRefusal`, `SecretMissingRefusal` | `contracts`, exists | Why a run was refused before any driver call: a plan run's reasons, an evidence run's, and the missing secret both share |
| Runtime denial | `Denial` | `contracts`, exists | Which policy rule the runtime guard stopped the run with, at which step, and whether the audit sink failed to record it |
| Result hash | `resultHash`, `withRunHashes` | `engine`, exists | What replay compares: sha256 of the result's canonical JSON without `timings`, the manifest body (`manifestHash` is in), `blockedOrigins` or the two hashes. A request sent as a run ends can change the list, so it is left out. Unkeyed, so an edit shows only against a copy of the hash held elsewhere |
| Evidence hash | `evidenceHash`, `withRunHashes` | `engine`, exists | The same hash with `blockedOrigins` covered, so an edit to that list is detectable. Replay never compares it. Unkeyed, so an edit shows only against a copy of the hash held elsewhere |
| Run lifecycle | `lifecycle` (`Planned`, `Resolved`, `Running`, terminal states including `Refused` and `Denied`) | `engine`, exists | The typed state machine every run walks; illegal transitions do not compile |
| Policy gate | `policyGate`, `PolicyGate` (`decide`, `clear`, `guardAction`), `PlanClearance`, `RunClearance`, `TargetClearance`, `ClearedRun`, `TargetNotDeclared`, `PlanDenial`, `GuardVerdict`, `PolicyRuleId` | gate in `engine`, types in `contracts`, exists | Narrows what a valid plan may do: a static check before the run and a runtime guard before every action. An allow is a `ClearedRun` per target both the plan and the matrix declare, holding the plan, project, target and standing it judged, and the only thing `run` takes; any other target gets a `TargetNotDeclared`, which ends TargetUnavailable with not-declared. Each denial appends a `plan.denied` audit event; a denial the audit sink failed to record is marked `unrecorded` |
| Cleared run | `ClearedRun`, made only by the policy gate; `assertCleared` checks it at run time | type and gate in `engine`, exists | A plan the policy gate cleared for one target, held together with the project, target and standing it was judged under. `run` takes nothing else. It has a private field no other module can reach, so an object written by hand neither type-checks as one nor passes the run-time check |
| Irreversible patterns | `IrreversiblePatterns`, `BUILT_IN_IRREVERSIBLE_PATTERNS`, `policy.allowedIrreversibleNames` | `contracts` and `engine`, exists | Words per locale (delete, pay, send, revoke and project additions) that mark an action as irreversible, matched as whole words after NFKC folding, removing invisible format characters and splitting camelCase; a locale with none is denied, and a plan with no targets is checked against every set |
| Resolved element | `ResolvedElement`, `ActionGuard` | `contracts`, exists | What a locator resolved to on the page (name, role, form submit control, link URL), handed to the runtime guard before an action, with the open dialog's text for a dialog step |
| Run manifest | `RunManifest` (`PlanRunManifest`, `EvidenceRunManifest`), `FixtureReference`, `HostInfo`, `SecretRecord`, `StorageStateRecord`, `UnsafeDeclarationRecord`, `RunVersions`, `EvidenceManifestRecord`, `isEvidenceManifest`, `manifestHash` | shape and `isEvidenceManifest` in `contracts`, `manifestHash` in `engine`, exists | Every input that decides a run's result, hashed, so the run can be replayed. A plan run's always names its target, adapter and browser; an evidence run's always holds its evidence record and none of those. See SPEC-08 |
| Run pins | `RunPins`, `RunVersions`, `runPins`, `projectHash` | type in `engine`, gathered by `cli`, exists | What a manifest pins about the machine and repository a run starts on: versions of Revisum, the ACT rule set, axe-core, Node and packs; hashes of the PII redactor, rule set, baselines and system fonts; the run image's id and the commit. Recorded only when a run is given them, so other manifests keep their hashes |
| Executable hash | `executableSha256`, `CheckedBuild`, `checkPinnedBuild` | `engine`, exists | The sha256 core takes of the browser executable before launching it, whenever the adapter reports its build, rather than trusting the reported version |
| Manifest decoder | `decodeManifest`, `MANIFEST_SCHEMA`, `DecodeError` | `engine/src/replay/`, exists | Reads a manifest back from JSON: another schema version or an unknown key is `version-unsupported`, a known field of the wrong shape a `replay-mismatch` at its JSON path |
| Replay | `replay`, `ReplayRequest`, `ReplayPorts`, `FixtureReader`, `ReplayOutcome`, `ReplayVerdict`, `ReplayError`, `PER_ENVIRONMENT_INPUTS` | `engine/src/replay/`, exists | Runs a recorded run again from its manifest and compares result hashes, which leave out `blockedOrigins`: `identical`, a `per-environment-baseline` (only the machine differs) or a `mismatch`, neither of the last two a pass. Checks the manifest, recording, plan, target and fixtures before any driver call |
| Recorded replies | `replay.recordReplies` (`ReplaySettings`), `RunRecording`, `RecordedServiceReply`, `RecordedCommandReply`, `RecordedBytes`, `RecordedReplyKind`, `recordingPorts`, `RecordingPorts`, `RepliedPorts`, `replayedServices`, `replayedDatabaseCommands`, `ReplayedPort`, `decodeRecording`, `RECORDING_SCHEMA`, `recorded-replies` | `engine`, exists | Opt-in: a trusted project that sets `replay: { "recordReplies": true }` keeps its runs' service responses and command outputs, with their requests' hashes, beside the result, so a replay feeds them back and sends nothing. Recordings may hold personal data until SPEC-09 masks them; without the setting such runs are `replay-not-claimed` |
| Secret echo | `SecretEcho`, `WrappingScheme`, `cutSecretEchoes`, `restoreSecretEchoes` | `engine/src/secrets/secret-values.ts`, exists | A secret's echo cut out of a recorded reply, in any form the leak scanner looks for, kept as where it goes back and how it was written, never the value; a replay puts it back from its own secret store |
| Benchmark | `tools/scheduled/BenchmarkRuns.ts`, `benchmarkRuns`, `docs/decisions/benchmark-baseline.json` | `tools`, `cli`, exists | The weekly performance trend alarm: 20 sign-up runs on the headless shell, median setup time and peak memory against the Linux baseline, a warning over 30%, never a gate |
| Logging manifest | `LOGGING_MANIFEST`, `manifestLogger`, `RunEventSink` | `engine`, exists | The only fields a run may log, with why and for how long; the sink a run's events go to. Not the audit `EventSink` of SPEC-27 |
| Redaction | `Redactor`, `defaultRedactor`, `SENSITIVE_PLACEHOLDER` | port in `contracts`, default in `engine`, exists | Masks personal-data elements in screenshots and personal-data patterns in kept text |
| Accessibility finding | `A11yFinding` (driver audit), `Finding` (own engine) | `contracts`, `auditor-act`, exist | One accessibility problem: a rule, its WCAG criteria, severity and the element's box |
| ACT rule, probe | `RuleMeta` with `kind: 'act-rule' \| 'probe'` | `auditor-act`, exists | A check that follows a W3C ACT rule, or a WCAG success criterion where no ACT rule exists |
| Tab walk | `tabWalk`, `TabWalk` | `auditor-act`, exists | Presses Tab through a page and records focus order, visible focus and occlusion |
| Report input | `ReportInput`, `ValidReport`, made only by `parseReportInput` | `report`, exists | The data a visual evidence report is rendered from |
| Acceptance criterion | `criterion` (`criterionId`, `CriterionId`, `criteriaInScope`) | on every plan assertion, exists | One observable behaviour a spec promises. Earlier name: AC |
| Change class | `changeClass` (`changeClassId`) | planned | The kind of change a pull request makes, which sets how much review it needs |
| Test set | `TEST_SET` | `tools/repo-rules/commits/CheckTestsApart.ts`, exists | Tests, proofs, fixtures and golden files: the paths that must change apart from code |
| Dependency review | `DependencyReview` with `DependencyCheck` items, `DEPENDENCY_REVIEWS` | `tools/repo-rules/docs/CheckDependencyReviews.ts`, reviews in `tools/repo-rules/docs/DependencyReviews.ts`, exists | The keep-or-drop test every third-party component on the trust path must pass. Earlier name: R11 test |
| Guarantee map | `GuaranteeMap`, `GuaranteeRow`, `GUARANTEE_MAP` | `tools/metrics/GuaranteeMap.ts`, exists | Each published guarantee, the CI test that proves it, the class shown when the test passes and the weaker class shown when it does not. Published as `docs/guarantees.md` |
| Test results | `tools/test-runner/TestResultLine.ts`, `readTestResults` | `tools/`, exists | One JSON line per test in `.test-results/`; a test id is `<file>#<full name>`. |
| Commit trailers | `readCommitTrailers`, `CommitTrailers`, `KNOWN_MALFORMED_COMMITS` | `tools/repo-rules/commits/CommitTrailers.ts` and `tools/metrics/ProjectMetrics.ts`, exists | The `Agent:`, `Spec:` and `Criteria:` lines the project's own metrics are read from |
| Repository rule | `RepositoryRuleName`, `REPOSITORY_RULES`, `runRepositoryRules` | `tools/repo-rules/RunRepositoryRules.ts`, exists | One of the checks `npm run lint` runs, all in one process; trust rules stay here because an ESLint suppression would be an opt-out |
| Naming lint | `NamingLintConfig`, `NAMING_LINT`, `lintRepository` | `tools/`, exists | Enforces the naming rules in CI |
| Declared approval | `DeclaredApproval`, strength `declared` | `contracts`, exists | An approval resting on the founder's own push or merge under the agent lock-down; labelled "declared, not verified" |
| Verified approval | `VerifiedApproval`, strength `verified` | `contracts`, exists | An optional approval by a code owner's review; never required. No gate, metric or level takes it (`tools/repo-rules/code/CheckApprovalStrength.ts`) |
| Approval | `Approval`, made only by `approvalVerifier`; `approvalLabel` | type in `contracts`, verifier in `engine`, exists | A person's approval of a subject (plan, trusted file, review decision, extra review or holdout plan), keyed by its hash, with a pseudonymous approver and the proof kind |
| Approval proof | `ApprovalProof` (`code-owner-review`, `agent-lockdown-merge`, `signature`) | `contracts`, exists | The evidence offered for an approval; the verifier checks it against GitHub and the protected branch |
| Agent lock-down | `AgentLockdown`, in `approvers.json` | `contracts`, exists | The owner's route: the coding agent is denied push, merge and pull-request approval, and the named maintainer pushes and merges |
| Unverified decision | `unverified` | `engine`, exists | A decision with no usable proof: an `unverified` actor (local) or an `agent` actor (MCP, token), never an Approval |
| Version-control port | `VersionControlPort`, `VersionControlReview` | `contracts`, exists | Read-only access to GitHub: protected-branch files, reviews, pull requests and who landed a commit |
| Trusted project | `TrustedProject` (`Provenance`), made only by `loadTrustedProject` | `engine`, exists | The project read from the protected branch, with where it came from. A trusted file the change edits raises a `changed-with-code` review item |
| Trusted file | `isTrustedFile` | `engine`, exists | `project.json`, `approvers.json`, `holdouts.json`, `plans/**`, `baselines/**` and the code-owners file; everything else is application code |
| Plan standing | `PlanStanding`, `planStanding`, `ownStanding`, `approvalFor`, `mergeGateOpen` | `engine`, exists | Approved when the plan's exact hash has an approval, otherwise a proposal; a standing whose approval is for another plan's hash counts as a proposal (`ownStanding`). | Readable plan | `.plan` text; `readPlanText`, `writePlanText`, `TextErrorCode` | `engine`, exists | The plain-text form of a plan, read into plain JSON for the one plan parser and written back from a Plan; `writePlanJson` writes the canonical JSON form. See SPEC-28 |
| Plan draft | `PlanDraft` (`PlanFormat`), `admitDraft`, `admitCoreDraft`, `DraftError` | type in `contracts`, door in `engine`, exists | What every authoring route produces: plan text, readable or JSON, never a Plan. `admitDraft` is the one door from a draft to a Plan; `admitCoreDraft` is the same door for core's own routes, which records them `core-recorded` |
